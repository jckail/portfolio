# Audit — 2026-09-06

Two rounds of parallel multi-agent review. Round 1 (six agents) covered backend
security, frontend code, infra/CI, build health, performance/SEO/a11y and
content. Round 2 (five agents) was pointed at **round 1's own fixes**, with
instructions to break them.

That framing was the most valuable decision in the exercise. Round 2 found
**four defects introduced by round 1**, including a live production outage.
Anything that fixes security deserves the same scrutiny as the code it fixes.

Companion documents:
- [`audit-2026-09-06-open-findings.md`](./audit-2026-09-06-open-findings.md) —
  the full backlog of everything confirmed but **not** fixed, with file:line and

## 1. Regressions introduced by round 1

| # | Defect | Impact | Status |
|---|---|---|---|
| R1 | WebSocket `Origin` check compared against `ALLOWED_ORIGINS` only | **Chat dead on 3 of 4 production hosts**, including the declared canonical | Fixed `14cd924` |
| R2 | `client_ip()` read the **leftmost** `X-Forwarded-For` hop | Every per-IP rate limit was attacker-selectable | Fixed `4eb5764` |
| R3 | `connect()` claimed the client id **after** `await accept()` | TOCTOU race leaked a connection slot permanently; 5 races locked a visitor out | Fixed `4eb5764` |
| R4 | Global `:focus-visible` used translucent `--primary-border` | Focus ring ~1.2:1 — invisible — in the **default** theme | Fixed `4eb5764` |
| R5 | `--accent-text` set on the wrong element for icon hovers | Fix was inert; icons stayed at 2.46:1 (light) and 1:1 (party) | Fixed `4eb5764` |
| R6 | `/api/*` `Cache-Control` applied to health and error responses | A cached "healthy" 200 would hide an outage from uptime alerting | Fixed `fe53cbb` |

**R1 in detail.** Production sets `ALLOWED_ORIGINS=https://www.jckail.com`, but
Cloud Run serves four domain mappings. Verified against production with a real
handshake: `www.jckail.com` → 101; `jckail.com`, `jordan-kail.com`,
`www.jordan-kail.com` → 403. Before the round-1 change there was no Origin check
at all, so the chat worked everywhere.

The fix is not "add the hosts to the env var" — it is that **same-origin is
never cross-site forgery**. Comparing the Origin's netloc to the request's Host
is both correct and independent of which hostname serves the app, so it cannot
break again when a domain is added.

## 2. Why the regressions escaped the tests

A mutation probe disabled one security control at a time and recorded whether
the suite noticed. **Score: 5 of 10 controls.**

| Mutation | Old result |
|---|---|
| Admin auth layer deleted entirely | **78/78 passed** |
| WebSocket `Origin` check removed | **passed** (in 300s) |
| `verify_access` dev-bypass always true | **passed** |
| `resume_routes` serves an arbitrary path | **passed** |
| Telemetry rate limiting disabled | **passed** |
| WebSocket `client_id` validation removed | **passed** |
| XSS guard, path traversal, open relay, contact limit, body caps | caught |

Two root causes, both now fixed:

**Tests that passed by timing out.** The WebSocket rejection tests wrapped
`receive_text()` in `pytest.raises(WebSocketDisconnect)`. With the guard
removed the socket is *accepted*, `receive_text()` blocks, and the server's
300-second idle timeout closes it — raising the expected exception anyway. The
test stayed green, just five minutes slower. This is precisely how R1 reached
production. They now assert the handshake is refused, with no `receive()` at
all: **2 seconds to fail, with a message naming the cause.**

**Assertions that never checked a status code.** The only test touching
`/api/admin/*` asserted a cache header. It held just as well when those routes
returned real data to an anonymous caller.

`backend/tests/test_admin_auth.py` now covers that boundary. Re-running the
auth-deletion mutation: **23 tests fail** where 0 did before.

## 5. Refuted

Recorded because acting on them would have *introduced* bugs:

- **"Repeated `--set-env-vars` flags don't accumulate in gcloud."** False — proven by gcloud's own duplicate-key error and `arg_parsers.UpdateAction`. `deploy.sh` applies all ten variables correctly.
- **"Dependabot doesn't update what production installs."** False — the open Dependabot branch modifies `requirements.lock.txt` (1031 lines).
- **"`react-hooks/exhaustive-deps` is silently disabled."** False — verified active via `--print-config` and a positive control. Zero findings is genuine.
- **The reported `ChatMarkdown` XSS.** Not real: React elements throughout, with a URL-scheme allowlist.

## 6. Fixed in this round

**Security** — same-origin WebSocket handling (R1); `X-Forwarded-For` read from
the right (R2); connect-race eliminated (R3); `--ws-max-size 65536` (default
16 MiB frames could OOM a 512Mi instance); `MAX_LOG_MESSAGE_CHARS` actually
enforced and no longer stored twice; newlines stripped so the log fallback
can't be used to forge entries; `/api/log` no longer returns provider
exception text; `re.fullmatch` for client ids; `removeprefix` for Bearer
tokens.

**Tests** — 78 → **105**, coverage 69.8% → **73.7%**, auth surface 39.8% →
**61%** (`auth_middleware.py` 39% → **100%**). Coverage floor 60 → 72 (it sat
10 points below actual, so it could never fire). New targeted CI gate on the
auth surface, because a global floor cannot see a weak auth layer inside a
well-covered codebase.

**Test isolation** — `conftest.py` used `os.environ.setdefault`, so a developer
with real credentials exported would have run the suite **against production**.
Now assigns unconditionally and refuses to start if `SUPABASE_URL` isn't a test
host.

**Dead code** — `backend/app/models/test_loader.py` deleted: 45 statements at
0%, and named `test_*` inside the app package, so any future `pytest backend/`
would have collected its `return True` functions.
