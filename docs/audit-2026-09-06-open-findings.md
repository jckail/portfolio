## 2. Frontend — confirmed defects

### F-1 · Body scroll lock missing on every modal — S2
`.modal-open` exists at `styles/components/modal.css:3` with **zero JS
references**. The only implementation is in dead code
(`shared/components/elements/modal/modal.tsx:33`), and `chat.tsx:53` explicitly
passes `disableScrollLock`.

Affects `SkillModal`, `ProjectModal`, `ExperienceModal`, `ContactModal`,
`command-palette`, the MUI chat dialog and `admin-login`. Second-order: the page
scrolls behind the modal, so `use-scroll-spy.ts:51` keeps rewriting the URL hash
underneath the user — on mobile, closing a modal leaves you elsewhere on the page.

Fix: a reference-counted `useScrollLock(active)` hook called alongside each
existing `useFocusTrap(true)`, plus an early return in the scroll-spy handler
while a lock is held.

### F-2 · Prototype-chain deep links crash a section — S2
`?skill=constructor`, `?skill=__proto__`, `?project=valueOf`,
`?company=hasOwnProperty` all reach a bare bracket lookup on a `JSON.parse`
object: `skills.tsx:229,232`, `about.tsx:188,191`, `experience.tsx:165,168,177,180`,
`projects.tsx:117,121,132,135`.

`skillsData['constructor']` returns `Object` — truthy — so the guard passes, the
modal mounts, and `skill.tags.map` throws. The section's `ErrorBoundary` replaces
it with "Something went wrong". Self-inflicted via a crafted link, but trivially
triggered.

Fix: an `own(record, key)` helper using `Object.prototype.hasOwnProperty.call`,
or store the payloads as `Object.assign(Object.create(null), data)` in
`data-provider.tsx` (which fixes every site at once, except the two literal maps
at `experience.tsx:112-131`).

### F-3 · Two dialogs open at once; Escape closes both — S2
`experience.tsx:165-186` renders `ExperienceModal` and `SkillModal` from
independent state, and `onSelectSkill={setSelectedSkill}` (`:173`) never clears
the experience. Clicking a tech-stack tag inside `ExperienceModal` mounts a
second dialog on top of the first.

Both `use-escape-key.ts:11` and `use-focus-trap.ts:52` attach to `document`, so
one Escape closes both, both Tab handlers fight over focus, and both dialogs
carry `aria-modal="true"` — which is invalid. `projects.tsx:127` gets this right;
`about.tsx:176-196` has the same latent shape.

Fix (minimal): clear the other selection in the handler. Fix (robust): make both
hooks stack-aware via a module-level token stack.

### F-4 · `admin-login` has no dialog semantics and a transparent panel — S2
`admin-login.tsx:41-49`: no `role="dialog"`, no `aria-modal`, no accessible
name, no Escape, no focus trap, no focus restore, no backdrop dismiss.

Additionally `styles/components/admin/admin-login.css:15` sets
`background: var(--background-color)`, which is **`transparent` in all three
themes** (`theme.css:5,36,67`) — so the credential form renders with no fill and
the page shows through it. Verified.

It also mounts twice (`main-content.tsx:87` for `/admin`, `admin-handler.tsx:39`
for Ctrl+Shift+A), so both can be open at once.

### F-5 · Cookie consent cannot be withdrawn — S2 (compliance)
`cookie-consent-portal.tsx:18` shows the banner only when consent is `null`, and
nothing else calls `setCookieConsent`. There is no settings link and no footer
entry. GDPR Art. 7(3) requires withdrawal to be as easy as granting.

Separately, `cookie-consent.ts:23-26` and `index.html:8-19` send only
`analytics_storage` / `ad_storage`. **Consent Mode v2** has required
`ad_user_data` and `ad_personalization` since March 2024.

### F-6 · Undefined CSS custom properties silently drop declarations — S3
`--spacing-s` and `--spacing-m` are used at `header.css:102,131,172,229` and are
**never defined** — `variables.css` declares only `-xs/-sm/-md/-lg/-xl`.
Verified: 4 usages, 0 definitions. An undefined `var()` makes the whole
`padding` shorthand invalid-at-computed-value-time, so it falls back to `0`.

Same class: `--primary-color` (8 uses) and `--primary-color-hover` (3) are
undefined. Mostly latent in dead code, but `modal.css:84`
(`.contact-info strong`) **is live** — the intended emphasis simply never renders.

### F-7 · `reading-progress.tsx` thrashes layout on every scroll event — S3
`:9-20` binds `update` raw to `scroll` and `resize` — no rAF gate, unlike
`use-scroll-spy.ts` and `side-panel.tsx` which have one. It reads
`doc.scrollHeight` and `window.innerHeight` (forcing layout), calls `setState`
per event, and writes `style={{ width }}`, which `reading-progress.css:20`
transitions — a layout-triggering property. Runs at the app root for the whole
session.

Fix: rAF-gate, cache the measurements, drive the bar with
`transform: scaleX()`, and add `aria-valuenow`.

### F-8 · Two duplicate `getBoundingClientRect` sweeps per frame — S3
`use-scroll-spy.ts:83-96` and `side-panel.tsx:30-49` each
`querySelectorAll('section[id]')` and measure all six sections every rAF tick.
The side-panel copy runs **even when the drawer is closed** — `SidePanel` is
mounted unconditionally by `header.tsx:112` and `useCurrentSection()` has no
`isOpen` gate.

Also, `<section id="doodle">` is always in the DOM, so both sweeps can select the
collapsed doodle section and set the hash to `#doodle`.

Fix: one shared `IntersectionObserver` writing to `section-store`; delete
`useCurrentSection` and read the store instead.

### F-9 · Root-level re-render and full-tree remount — S3
`app-logic-provider.tsx:25` destructures the entire zustand store, so it
re-renders on any field change — including `clickCount`/`lastClickTime`, which no
consumer reads. `:28-34` builds a fresh context object every render. It sits
above `ThemeProvider` and `App`, so this is the whole tree.

`app.tsx:95` `key={theme}` on `<ParticlesProvider>` unmounts and remounts
**all** of `MainContent`, `ChatPortal`, `CookieConsentPortal` and
`CommandPaletteHost` on every theme change: the chat WebSocket is torn down, the
transcript reloads from `sessionStorage`, every lazy section re-suspends, and any
open modal closes. `ParticlesCanvas` already reacts to `config` via props, so the
key buys nothing.

### F-10 · Heading structure and dialog naming — S3 (a11y)
`aria-labelledby` is used **0 times** in `src/` (verified); all five dialogs use
`aria-label` while a visible title sits right there.

Rank inversions: `SkillModal.tsx:62` `<h5>` title then `:89` `<h4>` sub-heading;
`ProjectModal.tsx:85` `<h5>`; `ContactModal.tsx:119` jumps h2→h5;
`header.tsx:96` uses `<h2>` for a tagline, outranking every real section heading.
None of the six `<section id=…>` elements has an accessible name.

### F-11 · Doodle: `aria-hidden` wrapping a focusable button; "open doodle" is a no-op — S3
`doodle.tsx:127` renders `aria-hidden={!active}` around a real `<button>` at
`:141`, and `doodle.css:77-82` hides the container with `max-height: 0; opacity: 0`
— **not** `visibility` or `display` — so the button stays in the tab order. That
is an axe-core `aria-hidden-focus` violation and a dead tab stop.

Separately, `chat-actions.ts:29-32` and `command-palette.tsx:45-50` "open" the
doodle by pushing `#doodle` and dispatching a synthetic `popstate`, but
`showDoodle` is only set in a **mount-only** effect (`main-content.tsx:108-116`)
with no `popstate`/`hashchange` listener. So the assistant's `navigate → doodle`
action and the palette command do nothing until reload.

### F-12 · `resume-provider` revokes a blob URL then stores it — S3

## 7. Investigated and refuted

Recorded so nobody re-opens them.

- **Repeated `--set-env-vars` don't accumulate in gcloud** — false. Proven by gcloud's duplicate-key error and `arg_parsers.UpdateAction`.
- **Dependabot doesn't update what production installs** — false. The open Dependabot branch modifies `requirements.lock.txt` (1031 lines).
- **`react-hooks/exhaustive-deps` is silently disabled** — false. Verified via `--print-config` and a positive control; zero findings is genuine.
- **XSS in `ChatMarkdown`** — not real. React elements throughout, `SAFE_URL` scheme allowlist, no `dangerouslySetInnerHTML` anywhere in `src/`.
- **Chat history is a stored-XSS surface via `localStorage`** — it is `sessionStorage`, per-tab, shape-validated on load.
- **Open redirect / reflected XSS in `custom_resolution.py`** — safe: `_SAFE_PATH_RE` blocks `:`, `//`, `\`, and every interpolation is `html.escape`d.
- **Path traversal in `zuni_routes` / `resume_routes`** — both safe; int coercion plus `os.listdir` membership, and a server-side filename respectively.
- **Timing attack on admin token comparison** — not applicable; no local secret comparison happens.
